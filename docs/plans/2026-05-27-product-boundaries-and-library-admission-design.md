# 产品边界与真实曲库自动入库设计

## 背景

HomeKTV 已经从演示曲库进入真实 NAS 曲库和 Android TV 播放阶段。当前更重要的是把产品边界固定下来，减少探索期遗留流程对真实使用的干扰。

## 已确认决策

- Admin 暂不加登录鉴权。
- 公网媒体流暂不做访问控制。
- Android TV APK 由用户本地打包后覆盖安装。
- 单音轨歌曲在手机控制端显示“单音轨歌曲源”。
- 真实曲库全自动索引和入库，不设置人工审核前置门槛。

## 方案

采用轻量家庭部署模型。安全边界由部署网络、Caddy、域名暴露范围和服务器访问策略负责；应用层不增加账号、媒体 token 或签名 URL。

真实曲库以 `ktv_*` 索引为准：只要资源 `missing_at is null`，搜索和点歌链路就可以展示并点歌。Admin 作为运维和诊断工作台，负责查看文件路径、可读性、技术元数据、播放失败和重新扫描结果，不承担人工审核职责。

控制端展示资源能力提示。后端搜索结果为索引版本返回 `audioTrackCount`；当值为 `1` 时，控制端显示“单音轨歌曲源”。该标签不阻止点歌，只提示这类资源没有双音轨原唱/伴唱切换能力。

## 数据流

1. 索引器写入 `ktv_song_assets.technical_metadata`。
2. 搜索 API 读取技术元数据里的 `mediaInfoSummary.audioTracks` 或兼容的 `audioTracks`。
3. API 返回 `audioTrackCount`。
4. 手机控制端根据 `audioTrackCount === 1` 展示标签。

## 验证

- 后端仓库测试覆盖 `audioTrackCount` 映射。
- 控制端测试覆盖单音轨标签展示。
- 文档记录 Admin、媒体访问、APK 安装和真实曲库自动入库边界。
