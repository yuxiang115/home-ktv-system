# KTV 一级目录解析规则设计

日期：2026-06-03

## 目标

让 `/mnt/nas/KTV歌曲` 下每个一级目录都固定到一个明确的文件名解析格式，避免当前只有少数目录能正确按文件名解析、其余目录退化成按路径猜测歌手和歌名。

## 当前问题

当前 parser 只对白名单根目录启用严格文件名规则：

- `流行歌曲*`
- `国语-知名歌星专辑*`
- `酷狗排行TOP`

这会导致其他一级目录即使文件名看起来统一，也会退回到 `path` 策略，出现：

- 把一级目录名误当歌手
- 把二级目录名误当歌名
- 丢失真实分类

抽样结果已经证明以下目录目前会被误解析：

- `1080P全高清MPG2026年更新（更新中）`
- `本店2026年更新MPG720超清（更新中）`
- `流行精选`
- `综合专辑 9300首1.4T`
- `网络热歌(有新歌加入)`

## 已确认约束

- 只按一级目录做规则绑定，不做更深层目录级配置。
- 先假设大多数目录共享同一条主文件名规则。
- `综合专辑 9300首1.4T` 有一个特殊点：歌曲名末尾括号中的内容是综艺名称，应该保留在标题里，不能被当成展示标记删掉。
- 先按这套分类落地，后续有异常目录再追加修正。

## 方案选型

### 方案 A：一级目录到解析 profile 的硬编码映射

做法：

- 在 `ktv-sample-index.ts` 中建立一级目录到解析 profile 的配置表。
- 每个 profile 决定是否启用严格尾部分段解析，以及标题末尾括号是否保留。

优点：

- 改动小，落点集中。
- 行为明确，可用测试锁定。
- 适合当前目录数量有限的真实歌库。

缺点：

- 新增一级目录时需要补代码映射。

### 方案 B：外部 JSON 配置

做法：

- 将一级目录规则抽到 JSON 或运行时配置文件。

优点：

- 未来增减目录不必改代码。

缺点：

- 当前明显过度设计。
- 需要额外处理配置加载、校验、默认值和文档。

### 方案 C：所有一级目录默认强制走同一严格规则

做法：

- 不做目录映射，直接对所有一级目录都尝试严格尾部解析。

优点：

- 实现最快。

缺点：

- 一旦有新目录命名不一致，就会静默误解析。
- 无法表达 `综合专辑` 这种“规则基本相同，但标题清洗行为不同”的特例。

## 推荐方案

采用方案 A。

## 详细设计

### 解析 profile

先引入两个 profile：

- `strict_dash_tail`
  - 适用于普通目录
  - 规则：`歌手-歌名-语种-分类.ext`
  - 从尾部识别 `语种` 和 `分类`
  - 第一段为歌手
  - 中间所有段拼回歌名
  - 标题末尾括号继续按当前逻辑剥离

- `strict_dash_tail_keep_trailing_parens`
  - 只用于 `综合专辑 9300首1.4T`
  - 基础解析与 `strict_dash_tail` 相同
  - 但保留标题末尾括号内容
  - 例如 `魔鬼中的天使(2018中国好声音)` 应完整保留

### 一级目录映射

本轮先固定为：

- `流行歌曲` -> `strict_dash_tail`
- `流行歌曲(2.5万首880G)` -> `strict_dash_tail`
- `流行精选` -> `strict_dash_tail`
- `网络热歌(有新歌加入)` -> `strict_dash_tail`
- `酷狗排行TOP` -> `strict_dash_tail`
- `国语-知名歌星专辑 11000首850G` -> `strict_dash_tail`
- `本店2026年更新MPG720超清（更新中）` -> `strict_dash_tail`
- `1080P全高清MPG2026年更新（更新中）` -> `strict_dash_tail`
- `综合专辑 9300首1.4T` -> `strict_dash_tail_keep_trailing_parens`

未列入映射的目录继续维持当前 fallback 行为，不扩大默认适用范围。

### 代码落点

- `apps/api/src/modules/ingest/ktv-sample-index.ts`
  - 将当前 `ruleForRootFolder()` 从“少量前缀判断”改为“目录 profile 映射 + profile 对应 parser”
  - 将严格尾部分段 parser 拆成可配置“是否保留末尾括号”的实现

- `apps/api/src/test/ktv-sample-index.test.ts`
  - 补最小必要测试
  - 覆盖新增目录映射和 `综合专辑` 的括号保留行为

## 错误处理

- 严格规则只在一级目录命中映射时启用。
- 如果命中的目录中存在不符合 `歌手-歌名-语种-分类` 的个别文件，仍按当前逻辑退回 `path` 或 `fallback`，不做强行纠错。
- 这能保证规则扩展后不会比现在更危险。

## 验证方式

- 为新增目录各补一个成功样例，确保都走 `filename`。
- 为 `综合专辑` 补一个样例，确保标题中的综艺括号不被删除。
- 跑 `apps/api/src/test/ktv-sample-index.test.ts` 的目标用例确认变更通过。

## 风险

- 部分目录内部可能夹杂少量异常文件名，仍会降级解析。
- `strict_dash_tail` 目前默认继续剥离标题末尾括号，若某些非 `综合专辑` 目录也需要保留括号，后续要继续细分 profile。
- 当前目录映射写在代码中，后续新增一级目录需要同步更新。
