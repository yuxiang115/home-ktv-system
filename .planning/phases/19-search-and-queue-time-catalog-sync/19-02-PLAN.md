  <behavior>
    - The service reads one selected active indexed asset by `indexedAssetId`.
    - Missing source rows or rows with `missing_at IS NOT NULL` reject with `KTV_INDEX_ASSET_STALE` and `索引已失效`.
    - Single-asset readability classification rejects non-readable paths with `KTV_INDEX_FILE_UNREADABLE` and `文件不可读`.
    - Successful sync upserts one canonical Song, one canonical Asset, and one source record.
    - Repeating sync for the same indexed asset returns the same canonical ids.
  </behavior>
  <action>
    Create `apps/api/src/modules/catalog/ktv-catalog-sync-service.ts`.

    Export:

    ```ts
    export interface KtvCatalogSyncResult {
      songId: SongId;
      assetId: AssetId;
      indexedSongId: string;
      indexedAssetId: string;
      sourceRecordId: string;
      status: "created" | "reused" | "updated";
    }

    export class KtvCatalogSyncError extends Error {
      code: "KTV_INDEX_ASSET_STALE" | "KTV_INDEX_FILE_UNREADABLE" | "KTV_INDEX_SYNC_FAILED";
      message: string;
    }

    export class PgKtvCatalogSyncService {
      constructor(db: QueryExecutor, options?: { checkFileAccess?: boolean; sampleTimeoutMs?: number; accessFile?: (filePath: string) => Promise<void> })
      syncIndexedAsset(input: { indexedAssetId: string }): Promise<KtvCatalogSyncResult>
    }
    ```

    The service query must join:

    ```sql
    ktv_song_assets a
    JOIN ktv_songs s ON s.id = a.song_id
    LEFT JOIN ktv_index_runs r ON r.id = a.last_seen_run_id
    ```

    Select at least:

    - `a.id`
    - `a.song_id`
    - `a.file_path`
    - `a.relative_path`
    - `a.file_name`
    - `a.extension`
    - `a.size_bytes`
    - `a.parse_confidence`
    - `a.missing_at`
    - `s.title`
    - `s.primary_artist_name`
    - `s.category`
    - `r.source_root`

    Reject stale rows before writing:

    ```ts
    throw new KtvCatalogSyncError("KTV_INDEX_ASSET_STALE", "索引已失效");
    ```

    When `checkFileAccess !== false`, call `buildNasSample` with one asset, `sourceRoot`, and `sampleTimeoutMs ?? 250`. If the result status is not `readable`, throw:

    ```ts
    throw new KtvCatalogSyncError("KTV_INDEX_FILE_UNREADABLE", "文件不可读");
    ```

    Use these deterministic ids:

    ```ts
    const songId = `song-ktv-${indexedSongId}` as SongId;
    const assetId = `asset-ktv-${indexedAssetId}` as AssetId;
    const sourceRecordId = `source-ktv-index-asset-${indexedAssetId}`;
    ```

    Upsert `songs` with:

    - `id = songId`
    - `title = ktv_songs.title`
    - pinyin/initials from `buildPinyinSearchKeys`
    - `artist_id = 'artist-ktv-' || normalized artist text`
    - `artist_name = ktv_songs.primary_artist_name`
    - `language = 'mandarin'`
    - `status = 'ready'`
    - `genre = ARRAY[category]` when category is non-empty, otherwise `{}`
    - `tags = ARRAY['ktv-index']`
    - `search_hints = ARRAY[category, extension, primary_artist_name]` with blanks removed
    - `canonical_duration_ms = 0`
    - `default_asset_id` updated after the asset upsert.

    Upsert `assets` with:

    - `id = assetId`
    - `song_id = songId`
    - `source_type = 'local'`
    - `asset_kind = 'dual-track-video'`
    - `display_name = file_name`
    - `file_path = file_path`
    - `duration_ms = 0`
    - `lyric_mode = 'none'`
    - `vocal_mode = 'dual'`
    - `status = 'ready'`
    - `switch_family = NULL`
    - `switch_quality_status = 'review_required'`
    - `compatibility_status = 'unknown'`
    - `compatibility_reasons = [{ code: 'ktv-index-playback-unverified', severity: 'warning', message: 'KTV indexed asset has not completed playback verification', source: 'scanner' }]`
    - `media_info_summary.fileSizeBytes = Number(size_bytes ?? 0)`
    - `media_info_provenance.importedFrom = 'ktv-index'`
    - `track_roles = { original: null, instrumental: null }`
    - `playback_profile = { kind: 'single_file_audio_tracks', container: extension without dot, videoCodec: null, audioCodecs: [], requiresAudioTrackSelection: false }`

    Upsert `source_records` with:

    - `id = sourceRecordId`
    - `asset_id = assetId`
    - `provider = 'ktv-index'`
    - `provider_item_id = indexedAssetId`
    - `source_uri = file_path`
    - `raw_meta` containing `indexedSongId`, `indexedAssetId`, `filePath`, `relativePath`, `title`, `primaryArtistName`, `category`, `extension`, `sizeBytes`, and `parseConfidence`.

    Add tests in `apps/api/src/test/ktv-catalog-sync-service.test.ts` proving:

    - first sync writes `song-ktv-ktv-song-1`, `asset-ktv-ktv-asset-1`, and `source-ktv-index-asset-ktv-asset-1`;
    - second sync of the same indexed asset returns the same ids and does not create a second source record;
    - source record `provider` is `ktv-index`, `provider_item_id` is the indexed asset id, and `source_uri` is the original file path;
    - `raw_meta` includes `parseConfidence`;
    - stale/missing row rejects with `KTV_INDEX_ASSET_STALE` and `索引已失效`;
    - unreadable path rejects with `KTV_INDEX_FILE_UNREADABLE` and `文件不可读`;
    - when an insert after song upsert fails, transaction-capable test harness proves no asset/source record is left behind.
